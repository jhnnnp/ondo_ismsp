## 1. 역할별 요약

### 디자이너

- 인상: 전문적, 신뢰감, 차분함, 명확함
- 피하기: 의료/체온계, 귀여운 교육 앱, 위협적인 보안 솔루션
- 히어로에서 CTA가 가장 먼저 보여야 함
- 온도(`°`)는 장식이 아니라 점수 체계의 심벌
- 카드 그림자는 거의 쓰지 않음. 테두리(`#DFE5EB`)로 구분
- 자물쇠, 방패, 불꽃, 빨간 체온계, 심전도, 병원 십자가 아이콘 금지

### 프론트엔드

- 첫 화면 필수 3요소: 서비스 정체성 / 얻는 것 / 시작 버튼
- 주요 CTA만 민트 버튼. 나머지는 텍스트 또는 고스트 버튼
- 내부 계산은 `%`, 화면 표시는 `72°` (단위는 `°`만, `°C` 금지)
- 상태 라벨과 점수 구간은 이 문서 7절을 따름
- 헤더는 `position: sticky`, 높이 72px
- 폰트: Pretendard 우선, 없으면 Noto Sans KR

### 카피 / 법무 확인

- `합격`, `인증 가능`, `인증 완료`, `인증 보장` 사용 금지
- 푸터 면책 문구는 수정 없이 그대로 노출
- KISA/한국인터넷진흥원 공식 서비스처럼 읽히는 표현 금지

### 로고 표기 (lockup)

영문 서브라인:

```text
ONDO°
ISMS-P Self Assessment
```

한글 서브라인 (랜딩 기본):

```text
ONDO°
ISMS-P 자가진단
```

- `ONDO`와 `°`는 한 덩어리로 취급. 줄바꿈하지 않음
- `°`는 본문 온도 표기와 동일한 글리프 사용
- 로고를 아이콘화할 때도 체온계/불꽃이 아니라 **원형 또는 반원형 게이지**에서 출발

## 3. 페이지 구조

스크롤 순서. 섹션 id는 앵커/헤더 메뉴와 맞출 것.

```text
1. Header          #header
2. Hero            #hero
3. Feature strip   #features
4. How it works    #guide
5. Result preview  #results
6. Differentiation #why
7. Final CTA       #start
8. Footer          #footer
```

권장 레이아웃:

- 콘텐츠 최대 너비: `1120px`
- 좌우 패딩: 데스크톱 `40px`, 모바일 `20px`
- 섹션 세로 리듬: 데스크톱 `96px`, 태블릿 `72px`, 모바일 `56px`
- 그리드: 8pt. 간격은 8의 배수 (`8 / 16 / 24 / 32 / 48 / 64 / 96`)

반응형 분기:

| 구간 | 레이아웃 |
| --- | --- |
| ≥ 1024px | 히어로·결과 예시 2열 |
| 768–1023px | 히어로 1열(카피 위, 미리보기 아래). 기능 요약은 2×2 |
| < 768px | 전부 1열. 헤더 메뉴는 햄버거. CTA는 헤더에 아이콘/짧은 버튼 유지 |

## 4. 섹션 스펙

### 4.1 Header

높이: `72px`
배경: `#FFFFFF` 또는 `#F5F7FA`
하단: `1px solid #DFE5EB`
스크롤 시 `position: sticky; top: 0; z-index: 50`

```text
[ONDO°]                                              서비스 소개   진단 항목   이용 안내   로그인   [자가진단 시작하기]
```

| 요소 | 동작 |
| --- | --- |
| 로고 | `/` 또는 `#hero` |
| 서비스 소개 | `#why` 또는 `#features` |
| 진단 항목 | `#results` |
| 이용 안내 | `#guide` |
| 로그인 | 로그인 페이지. 미구현이면 숨기거나 disabled 처리하지 말고 스펙에 맞게 연결 |
| 자가진단 시작하기 | 진단 시작. 기존 `/controls/map` 진입 |

규칙:

- 메뉴는 **최대 4개** (로그인 제외, CTA 제외)
- 민트 솔리드 버튼은 CTA 하나뿐
- 로그인은 텍스트 링크. 버튼으로 만들지 않음

### 4.2 Hero

첫 뷰포트에서 반드시 보여야 하는 것:

1. ISMS-P 자가진단 서비스라는 점
2. 무엇을 얻을 수 있는지
3. 어디를 눌러 시작하는지

**왼쪽 카피**

```text
ISMS-P SELF ASSESSMENT          ← kicker, 12–13px, tracking +0.08em, #7E8A99

우리 조직의
인증 준비 온도는?               ← display, 40–56px, 700–800
                                 「온도」만 #20A786

ISMS-P 요구사항을 기준으로 현재 준비 수준을 진단하고,
우선 보완해야 할 항목을 명확하게 확인하세요.

[자가진단 시작하기 →]           ← Primary CTA
[진단 방식 알아보기]             ← Ghost / text, #guide로 스크롤

회원가입 없이 체험 가능 · 예상 소요시간 약 15분
```

제목은 두 줄 고정. 한 줄로 이어 쓰지 않음.

```text
우리 조직의
인증 준비 온도는?
```

**오른쪽 비주얼 — 결과 미리보기 카드**

실제 결과 화면처럼 보이게. 장식 일러스트 대신 UI 목업.

```text
진단 결과 미리보기                         준비 진행 중

                    ISMS-P 준비 온도

                            72°

                    지난 진단 대비 +8°

관리체계 수립 및 운영                         84°
████████████████░░░

보호대책 요구사항                             68°
█████████████░░░░░░

개인정보 처리단계별 요구사항                   61°
████████████░░░░░░░
```

게이지 규칙:

- 원형 또는 반원형 게이지. **의료용 세로 체온계 금지**
- 단위는 `°`만. `°C` 금지
- 숫자 위 또는 아래에 반드시 `ISMS-P 준비 온도` 표기
- 스케일 0–100
- 무지개 그라데이션 금지. 트랙 `#DFE5EB`, 채움 `#20A786` 또는 구간 색 1개
- 사람, 심전도, 병원 십자가 아이콘 금지
- 영역 바는 단색 + 옅은 트랙. 영역마다 다른 무지개 색 쓰지 않음
  - 84° 준비 양호 `#20A786`
  - 68° 준비 진행 `#3B82D0`
  - 61° 준비 진행 `#3B82D0` (60–79 동일 구간)

카드 스타일:

- 배경 `#FFFFFF`
- 테두리 `1px solid #DFE5EB`
- radius `16px`
- shadow는 `0 8px 24px rgba(18, 38, 56, 0.04)` 이하. 더 강하게 쓰지 않음
- 우측 배지 `준비 진행 중`은 `#3B82D0` 소프트 배경

### 4.3 Feature strip

히어로 바로 아래. 큰 카드 4장이 아니라 **얇은 가로 텍스트 바**.

```text
복잡한 인증 준비를 더 명확하게

항목별 자가진단  |  영역별 준비도 분석  |  보완 우선순위 안내  |  진단 이력 비교
```

- 구분: 세로 `1px #DFE5EB`
- 아이콘이 필요하면 12–16px 라인 아이콘 1개. 방패/자물쇠 남발 금지
- 배경은 페이지 배경과 같거나 카드 화이트 한 줄

### 4.4 How it works (`#guide`)

제목:

```text
체크에서 끝나지 않는
준비 수준 진단
```

설명:

```text
답변을 점수로만 환산하지 않습니다.
준비 수준과 미흡 항목, 다음 행동까지 하나의 흐름으로 연결합니다.
```

3열 카드. 번호는 `01 / 02 / 03`, 영문 스텝은 작은 kicker.

| 스텝 | 영문 | 제목 | 본문 |
| --- | --- | --- | --- |
| 01 | CHECK | 요구사항별 자가진단 | ISMS-P 인증기준에 따라 조직의 현재 관리현황을 단계적으로 확인합니다. |
| 02 | ANALYZE | 준비 온도 시각화 | 전체 준비 수준과 영역별 상태를 직관적인 게이지로 확인합니다. |
| 03 | IMPROVE | 보완 우선순위 확인 | 미흡한 항목과 개선 순서를 확인하고 재진단으로 변화를 추적합니다. |

카드: 화이트, 얇은 테두리, 그림자 없음 또는 hairline.

### 4.5 Result preview (`#results`)

제목:

```text
결과는 간단하게,
보완할 항목은 명확하게
```

2열:

**왼쪽 — 영역별 온도**

```text
전체 준비 온도                 72°

관리체계 수립 및 운영          84°
보호대책 요구사항              68°
개인정보 처리단계별 요구사항    61°
```

**오른쪽 — 개선 목록**

```text
우선 보완이 필요한 항목

높음  개인정보 보유기간 검토
높음  접근권한 정기점검
중간  개인정보 처리방침 현행화
중간  수탁자 관리·감독 기록
```

우선순위 배지:

- 높음 → `#D96060` (우선 보완). 배경은 연한 레드, 텍스트는 레드
- 중간 → `#E7A43B` (확인 필요)
- 빨간색은 이 목록과 위험 항목에만 사용

이 섹션의 메시지는 점수보다 **보완 항목**이 시각적으로 더 무거워야 함.
왼쪽 게이지가 장식이 되고 오른쪽 목록이 본문이 되도록 타이포 위계를 잡을 것.

### 4.6 Differentiation (`#why`)

제목:

```text
왜 ONDO°인가요?
```

4항목. 2×2 또는 4열. 아이콘은 절제.

| 제목 | 본문 |
| --- | --- |
| 인증기준 기반 | ISMS-P 인증기준에 따라 진단 항목을 체계적으로 구성합니다. |
| 한눈에 보는 준비도 | 복잡한 진단 결과를 영역별 준비 온도로 시각화합니다. |
| 행동으로 이어지는 결과 | 점수만 제시하지 않고 우선 보완해야 할 항목을 안내합니다. |
| 지속적인 변화 확인 | 재진단을 통해 이전 결과와 현재 준비 수준을 비교합니다. |

버튼 호버는 `#168F74` → `#127A63`. 그림자로 강조하지 않음.

기존 control map 토큰과의 관계:

| 랜딩 | 기존 `tokens.css` | 조치 |
| --- | --- | --- |
| `#20A786` / `#168F74` | `--accent: #0f766e` | 랜딩은 ONDO 토큰 사용. 제품 본체 이관은 별도 작업 |
| `#122638` | `--text: #1d1d1f` | 랜딩 네이비는 더 차갑고 문서적 |
| Pretendard | Outfit + Noto Sans KR | 랜딩은 Pretendard. 제품 본체 폰트 교체는 후속 |

### 5.4 타이포그래피

우선순위: **Pretendard > SUIT > Wanted Sans > Noto Sans KR**

## 7. 점수 · 상태 체계

사용자에게는 온도, 내부 저장은 퍼센트. `display = Math.round(percent)` + `°`.

### 온도 구간 (랜딩 · 결과 화면 공통 목표)

| 구간 | 라벨 | 색 |
| --- | --- | --- |
| 0–39° | 준비 시작 | `#D96060` |
| 40–59° | 확인 필요 | `#E7A43B` |
| 60–79° | 준비 진행 | `#3B82D0` |
| 80–94° | 최종 점검 | `#20A786` |
| 95–100° | 높은 준비 수준 | `#20A786` |

100°를 **인증 가능**이라고 쓰지 않음.

### 항목/상태 명칭 (통일)

- 미진단
- 확인 필요
- 보완 필요
- 준비 진행
- 최종 점검

사용 금지: `합격`, `인증 가능`, `인증 완료`, `양호(인증 의미로)`, `적합`

### 결과 문구 템플릿

```text
현재 ISMS-P 준비 온도는 72°입니다.

전체 102개 항목 중
74개 항목이 준비된 것으로 확인되었습니다.
우선 보완이 필요한 항목은 12개입니다.
```

숫자 102 / 74 / 12는 예시. 실제 화면에서는 진단 집계값을 넣는다.
랜딩 목업은 위 숫자를 그대로 써도 된다.

### 기존 제품과의 차이 (구현 시 주의)

현재 본체 `src/isms_pii_toolkit/score_metrics.py` 구간:

| 기존 | 랜딩 가이드 |
| --- | --- |
| 80+ 양호 | 80–94 최종 점검, 95–100 높은 준비 수준 |
| 60+ 보통 | 60–79 준비 진행 |
| 35+ 보완 필요 | 40–59 확인 필요 |
| 0+ 기초 보완 필요 | 0–39 준비 시작 |

랜딩 카피와 게이지는 **이 가이드 구간**을 따른다.
제품 본체 라벨(`양호/보통/보완 필요`)을 랜딩에 가져오지 말 것.
본체 점수 체계 이관은 별도 작업으로 잡는다.

## 10. 프론트엔드 구현 노트

### 정보 구조

랜딩은 마케팅 셸이다. 진단 본체(`control_map.html`)와 분리한다.

권장:

```text
/                    랜딩 (이 스펙)
/controls/map        자가진단 본체
```

헤더·최종 CTA의 `자가진단 시작하기`는 `/controls/map`으로 이동.
로그인 엔드포인트가 아직 없으면 헤더에서 로그인만 빼고, 메뉴 한도를 맞춘다.

### 접근성

- 히어로 제목은 `h1` 하나. 「온도」색만 바꿔도 문장은 하나의 heading
- Primary 버튼 대비율: `#168F74` on `#FFFFFF` 확인 (WCAG AA)
- 네이비 위 민트 버튼도 AA 확인
- 게이지는 `role="img"` 또는 `meter` + 텍스트 대체
- 스티키 헤더 높이만큼 `scroll-margin-top: 72px`를 섹션에 부여
- 모션: 게이지 fill은 600–800ms ease-out. `prefers-reduced-motion`이면 즉시 표시

### 히어로 CTA 우선순위

첫 화면에서 기능 설명 카피보다 버튼이 먼저 스캔되어야 한다.
모바일에서 미리보기 카드가 CTA를 뷰포트 밖으로 밀면, 카피+버튼이 먼저 오고 카드는 그 아래.

### 구현하지 말 것 (랜딩 범위 밖)

- 실제 로그인 플로우 UI 신규 설계 (연결만)
- 진단 문항 화면
- 공식 인증서 배지, KISA 로고
- 온도를 날씨/체온 UX로 확장
