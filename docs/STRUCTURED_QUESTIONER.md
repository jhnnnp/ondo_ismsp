## 1. 문제 인식

자가진단을 1~2명이 돌릴 때, 그 사람들이 시스템/외주/로그/암호화 실태를 **완벽히** 알 가능성은 낮다.  
입력이 추측이면 “갭 리포트”는 그럴듯한 오답일 수 있다.

그래서 성공 기준을 바꾼다.

| 잘못된 성공 기준 | 올바른 성공 기준 |
| --- | --- |
| 심사 결과 예측 정확도 | **다음에 확인할 질문/담당/증적**이 명확해짐 |
| 준비도 %의 “정답성” | **모름(unknown)/추정**이 드러나고 줄어듦 |
| 101개 통제를 다 채움 | **지금 물어볼 10개**가 나옴 |

## 2. 제품이 하는 일 / 하지 않는 일

### 한다

1. 조직 맥락(규모/업종/클라우드/외주/PII)으로 **먼저 볼 범위**를 좁힌다.
2. 통제/체크 항목을 **확인 질문**으로 바꾼다. (“이행했나?”보다 “누구에게 무엇을 물어보나?”)
3. 답/모름/추정에 따라 **때문에 → 문제 → 야기** 가설을 보여 준다.
4. 결과의 1순위는 결함 단정이 아니라 **확인 액션 리스트**다.

### 하지 않는다

- 증적 없이 합격/불합격 단정
- 담당자 확인 없는 “완료” 확정
- 문서 RAG로 판정 대체 (후순위, 판정과 분리)

## 3. 사용자 경험 (목표 UX)

```text
1) 우리 조직은 어떤가?     → 프로파일
2) 어디부터 보지?         → 범위 초안 / 우선 통제
3) 이 항목, 내가 아나?     → 확인됨 / 추정 / 모름
4) 모르면 누구에게 묻지?   → 담당/질문/최소 증적
5) 답이 이렇게면?         → 인과 가설 (때문에→문제→야기)
6) 다음에 할 일 10개       → 확인 액션 (분석 결과의 주인공)
```

**기본 화면 한 줄 (2026-07-29 고정):**  
제품 본체는 자가진단. 기본 화면은 이번 세션 우선 통제 카드에서 **진단 상태**를 남기고, 나머지는 대기열·전체 진행 M/N으로 보여 준다. 상세: [`UX_PRINCIPLES.md`](UX_PRINCIPLES.md).

핵심 카피:

> “검사가 끝났습니다”가 아니라  
> **“아직 확인이 필요한 것부터 정리했습니다.”**

## 4. 이미 있는 재료 → 질문기로의 재해석

| 기존 기능 | 질문기에서의 역할 |
| --- | --- |
| 조직 프로파일 | 질문 범위를 줄이는 컨텍스트 |
| 범위 초안 / scopeReview | “경계에 뭐가 들어가는지” 확인 질문 |
| 최소 증적 세트 | “뭘 가져와야 답이 되는지” |
| 성숙도 4칸 | 이행도 러프 신호 (단독 판정 아님) |
| 도메인 체크 (`domainChecks`) | 구체 확인 문항 |
| CausalFinding | “이 답을 가정하면 생기는 가설” |
| 미리보기 | “이 항목을 확인하면 어떤 가설이 사라지나” |
| Verbalize | 가설 AI 리포트 (facts-only) |

부족한 것 (다음 구현 축):

1. ~~항목별 **입력 신뢰도** `confirmed | assumed | unknown`~~ → API/UI 1차 반영 (`inputConfidence` / 배너)
2. ~~결과 상단 **확인 액션 큐**~~ → `confirmationActions[]` + 기본 탭 “확인하러 갈 것”
3. ~~준비도 옆에 **입력 신뢰도 배너**~~ → analyze 뷰 상단
4. ~~카피/면책: 가설/확인 필요 톤 고정~~ → `control_map.html` 브랜드/CTA/탭 문구 반영 (2026-07-28)
5. ~~껍데기 입력 제거~~ → 체크해도 엔진 결과/보고서가 안 바뀌는 UI 제거 (범위 초안, soft 프로파일 플래그, 증적 스텁, 점검화면 LLM 토글, 조직 우선 뱃지)

### 1타 강사 퀘스트 (2026-07-27)

- 프로파일 `usesCloud` + `hasOnPremFacility=false` → 물리/전산실(2.4.1~2.4.6) **N/A**, readiness 분모 제외
- Quest 오버레이 KB (`data/quest_kb/`) — **101개 통제 전부 파일럿**, thin은 폴백 엔진으로 유지
- 물리 DC 통제(2.4.1~2.4.6)는 클라우드-only 시 N/A 안내 문구 포함
- 핵심 통제는 `CONTROL_CHECKLIST`로 형제 통제 공용 체크리스트를 분리
- confirmationActions는 체크 라벨을 질문형(~있나요?)으로 변환해 노출
- UI는 구어 퀘스트 톤, 분석 탭/인증 흐름 탭도 일상어로 정리
- 범위 초안 확인 질문은 `~나요?` 톤으로 정리
- 로컬 증적 스텁(파일명 메타)으로 퀘스트 완료 ↔ `evidenceSlots` 연결
- GPT Verbalize는 report + quest 문장만; actionId/controlId/점수/N/A는 결정론 엔진 소유

## 5. 확인 액션 스키마 (초안)

```json
{
  "actionId": "ask-2.9.4-2",
  "priority": 1,
  "controlId": "2.9.4",
  "question": "개인정보 처리 시스템 접속기록 보관 기간이 정책/법령 기준을 충족하는지?",
  "askWho": ["인프라/보안", "개인정보 보호책임자"],
  "evidenceHint": "로그 보관 설정 캡처, 보존 정책 조항",
  "confidence": "unknown",
  "whyItMatters": "미확인 시 사고 후 행위자 증명/심사 대응 가설이 남습니다.",
  "relatedFindingIds": ["2.9.4:2"]
}
```

분석 API 응답에 `confirmationActions[]`를 1급으로 두고, UI 기본 탭을 “갭 목록”이 아니라 **“확인하러 갈 것”**으로 둔다.

## 6. 성공 지표 (Lab 기준)

- unknown/assumed 비율이 진단 반복 후 감소하는가
- 확인 액션을 보고 실제 담당자에게 질문으로 이어지는가 (정성)
- 사용자가 결과를 “합격선”이 아니라 “숙제 목록”으로 이해하는가
