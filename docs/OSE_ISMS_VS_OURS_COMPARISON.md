# OSE-ISMS Guard vs 본 프로젝트 비교

> 기준일: 2026-07-22  
> 비교 대상: [(주)오상테크놀로지 OSE-ISMS Guard](https://www.osangtech.co.kr/OSE-ISMS.html) ↔ `isms-p-pii-toolkit` ISMS-P Lab  
> 전제: 오상은 **공개 마케팅/아키텍처 자료** 기준. 본 프로젝트는 **현재 코드/README** 기준.  
> 목적: “누가 더 완성된 인증 제품인가”가 아니라, **실제 ISMS-P 흐름 대비 어디가 비고 어디가 센지**를 정리한다.

## 1. 한눈에 보는 총평

| 관점 | 오상 OSE-ISMS Guard | 본 프로젝트 |
| --- | --- | --- |
| 제품 성격 | SI형 GRC 포털 + RAG 챗봇을 ISMS-P에 수직화 | PII 툴킷 위의 결정론적 자체진단/인사이트 Lab |
| 진입점 | 통제 체크리스트/대시보드부터 | 조직 프로파일 → 범위 초안 → 자가진단 |
| AI 역할 | 문서 검증/설명/보고서 생성까지 넓게 (RAG/LLM 판정) | 구조화 추론은 규칙/KB, LLM은(가정) 서술만 |
| 조직 컨텍스트 (규모/업종/범위) | 공개상 거의 없음 | 구현 (인원/업종/PII/클라우드/외주/원격/주민번호) |
| 증적/워크플로 | 강함 (업로드/버전/조치/알림) | 약함 (힌트/정적 매핑 위주) |
| 통제 간 인과/복합 결함 | 공개상 약함 | 강함 (그래프/멀티갭/Problem KB) |
| 시장 포지션 | 납품/세일즈 UI에 유리 | 학습/면접/기술-통제 연결 설명에 유리 |

**남은 공통 한계:** 범위/위험수용/증적 진위는 여전히 사람이 확정해야 한다. 본 프로젝트의 범위 초안은 인증 경계를 확정하지 않는다.

## 3. 본 프로젝트 — 부족한 점

1. **범위/자산/위험평가의 “실데이터” 입력은 아직 초안 수준**  
   프로파일 기반 범위 검토 초안과 확인 질문은 있지만, 실제 범위서/자산목록/데이터흐름 파일을 모델로 받아 검증하지는 않는다.

2. **증적/조치 운영 GRC가 약함**  
   업로드, 버전관리, 담당자 RACI 강제, 이행 점검 사이클, 알림/일정 같은 운영 포털 기능이 없다.

3. **제품화/지속 운영 레이어 부재**  
   localStorage 기반 Lab, 멀티테넌트, SSO, 감사로그 제품급 운영은 비목표에 가깝다.

4. **Verbalizing은 옵션 레이어**  
   `verbalize=true`일 때만 facts-only LLM 서술을 시도하며, 핵심 판정/수치는 여전히 결정론 엔진이다.

5. **시나리오 도메인 KB는 확장됐지만 깊이는 제한적**  
   의료/공공/금융/IT 시나리오를 추가했으나, 업종별 체크리스트/증적 예시는 아직 리테일 학습 수준이다.

6. **인증 “완주” 도구가 아님**  
   README도 명시하듯 실제 심사를 대체하지 않는 학습/자체진단 레이어다.

## 4. 오상 OSE-ISMS Guard — 부족한 점

1. **조직 규모/범위부터 시작하지 않음**  
   UI/카피가 통제표/준수율/AI 코파일럿으로 바로 간다. ISMS-P의 앞단(누가/무엇을/어디까지)이 제품 중심축이 아니다.

2. **판정이 LLM/문서 RAG에 과도하게 의존할 가능성**  
   증적 업로드 → “심사관 관점” LLM 검증 구조. 환각/일관성/근거 재현성 위험이 있다. 통제 간 결정론 그래프는 공개되지 않았다.

3. **마케팅 용어 대비 기술 검증 부족**  
   “5-Brain AI”, “AI MainNet”, “AI CISO”, ROI 25.8배, 준비 3개월→2주, GS 1등급 **예정** 등은 독립 검증/고객 실명 레퍼런스가 약하다.

4. **보안 추론 코어보다 GRC 껍데기가 두꺼움**  
   공개 아키텍처는 PostgreSQL/pgvector + RAG + 워크플로. “왜 이 통제 묶음이 위험한지”의 구조화 KB/멀티갭 엔진은 보이지 않는다.

5. **순수 보안 벤더라기보다 SI 확장 제품**  
   본업은 병원/공공 웹/SI. OSE-ISMS는 RAG 제품군의 수직화로 보이며, 시장 평판/보안 전문매체 검증은 초기 단계다.

6. **준수율/잔여위험 숫자 mid-funnel의 함정**  
   조직 컨텍스트 없이 체크리스트 합산한 “85%”는 심사에서 거의 의미가 없다. 보기 좋은 대시보드 ≠ 인증 준비도.

7. **적용 예외/규모별 깊이 조절이 불명확**  
   같은 1.1.3이라도 5인 스타트업과 상급종합병원은 요구 깊이가 다른데, 공개 자료상 프로파일 기반 테일러링이 드러나지 않는다.

## 5. 본 프로젝트 — 좋은 점

1. **결정론적/설명 가능한 추론**  
   통제 그래프, Problem KB, 멀티갭 규칙으로 “왜 이 갭인지”가 코드/JSON에 고정된다.

2. **복합 결함(멀티갭) 서술**  
   암호화만 있고 키관리/로그가 없는 식의 **묶음 취약**을 우선순위와 조치 워크스트림으로 낸다.

3. **기술 구현 ↔ 통제 연결**  
   PII scan/redact와 `3.2.1`, `2.9.4`, `2.7.1` 등 정적 브릿지로 “코드가 곧 인증이 아님”을 학습 가능하게 한다.

4. **한계를 문서에 명시**  
   학습용, 비목표(DB 탐지/운영 GRC 대체 아님)를 README에 분명히 적어 과장 리스크가 낮다.

5. **카테고리 심층/시나리오 가중**  
   영역/카테고리 readiness, 시나리오 관련 갭 하이라이트로 단순 체크리스트보다 한 겹 깊다.

6. **조직 프로파일 기반 진입**  
   인원/업종/PII/클라우드/외주 등을 먼저 받아 범위 초안과 우선 통제 가중을 적용한다. 프로파일이 없으면 기존 진단 계약을 유지한다.

7. **차별화 방향이 명확**  
   오상식 RAG 포털을 따라가기보다, **조직 프로파일 → 범위 초안 → 규칙 추론 → (선택) Verbalizing** 경로를 유지한다.

## 6. 오상 — 좋은 점

1. **증적/조치 중심의 운영 UX**  
   업로드, 버전, 조치계획, 이행 점검, 알림/일정 등 “담당자가 매일 쓰는 화면” 스토리가 강하다.

2. **원스톱 포털로 보이기 쉬운 구성**  
   대시보드/자가진단/코파일럿/위협맵을 한 제품처럼 묶어 영업/데모에 유리하다.

3. **문서 AI(RAG) 제품화 경험**  
   OSE-RAG와 스택을 공유(LangChain, Vector/Hybrid Search, Reranker, Gemini 등). 문서 질의/초안 생성은 익숙한 패턴이다.

4. **병원/공공 납품 채널**  
   웹어워드/상급종합병원 SI 실적으로 B2B 진입로가 있다. ISMS를 “기존 고객 확장”으로 팔 수 있다.

5. **엔터프라이즈 인프라 언어**  
   GCP/K8s, OAuth2, MSA, 역할기반 접근 등 구매 담당자가 익숙한 키워드를 갖췄다.

6. **유지관리/의무화 타이밍 마케팅**  
   2027 ISMS-P 의무화 서사와 맞물려 “지금 준비” 메시지 전달이 명확하다.

## 8. 시사점과 구현 현황

오상을 따라 **RAG/대시보드/증적 포털**을 먼저 키우기보다, 양쪽이 동시에 비어 있는 지점인 **조직 컨텍스트**를 먼저 닫는 편이 차별화에 유리하다.

2026-07-22 기준 다음 핵심 기반을 구현했다.

1. **조직 프로파일 intake (구현)**  
   예: 인원 구간(1~50 등), 업종, PII 규모, 클라우드/외주 여부  
   → API/UI/localStorage 입력 흐름

2. **범위 초안 생성 (구현)**  
   프로파일 → 서비스/시스템/위탁 경계 템플릿 + `1.1.4`/`1.2.x` 우선 묶음

3. **기존 규칙엔진에 가중치 연결 (구현)**  
   규모/클라우드/외주/원격접속/PII 규모에 따라 통제/멀티갭/Problem KB 조치 순서를 조절한다. 프로파일이 없으면 기존 점수와 갭 동작을 유지한다.

추가 구현(2026-07-23):

4. **업종별 독립 시나리오**  
   의료/공공/금융/IT 시나리오를 리테일 예시와 분리하고, 프로파일 추천 ID를 실제 시나리오와 정합시켰다.

5. **범위 초안 편집**  
   포함 경계 체크/확인 질문 응답(`scopeReview`)이 우선 통제와 검토 메모에 반영된다.

6. **최소 증적 세트**  
   업로드 GRC 없이 프로파일별 필수 증적 후보 목록을 제공한다.

7. **(선택) Verbalizing (구현)**  
   Context Packet 기반 facts-only 서술 + Self-Correction(통제 ID/수치/저신뢰 거부) + 템플릿 폴백

다음 고도화 (착수):

8. **인과 검색(Causal Retrieval)** — `docs/CAUSAL_RETRIEVAL_ROADMAP.md`  
   체크 미충족 → 문제 → 야기 리스크를 API/UI 1급 객체로 고정. Structured Retrieve 우선, 문서 RAG/증적 GRC는 후순위.

9. **증적 GRC는 후순위**  
   오상이 이미 두꺼운 영역. 우리가 따라가면 차별이 희석된다.

범위 초안은 법적/심사상 범위를 확정하지 않으며, 위험수용/증적 진위/운영 실재성은 사람이 확인해야 한다.
